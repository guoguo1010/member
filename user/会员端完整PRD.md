# 1. 入口与导航

## 1.1 个人中心

# 个人中心页面 PRD (产品需求文档)

## 1. 引言

### 1.1 背景

个人中心是中国农学会会员管理系统的会员端首页，为注册会员提供个人信息概览、快速操作入口、待办事项提醒等服务。帮助会员快速了解自身会员状态、完成日常操作。

```
中国农学会会员管理系统 - 会员端核心入口
```

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 个人会员 | 已注册并通过审核的个人用户，非黑名单用户 | 查看个人信息、办理会员业务 |
| 单位会员 | 已注册并通过审核的单位用户 | 查看单位信息、单位缴费 |
| 注册用户 | 非会员用户 | 注册个人会员、单位会员等 |

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
| ---------------- | -------------- | -------------- |
| 顶部导航栏 | Logo区域 | 显示中国农学会Logo和名称 |
| 顶部导航栏 | 导航菜单 | 首页、会员信息（个人会员身份时展示，黑名单会员不展示）、缴费订单、我的消息、成长轨迹 |
| 顶部导航栏 | 消息通知 | 显示未读消息数量气泡，点击跳转消息列表 |
| 顶部导航栏 | 用户下拉菜单 | 切换身份、账号设置、意见反馈（根据管理关开关展示）、退出登录 |
| 欢迎卡片 | 问候语 | 根据时间显示"早上/下午/晚上好"，显示用户姓名 |
| 欢迎卡片 | 会员状态 | 显示会员类型、编号，点击弹窗查看会员证 |
| 欢迎卡片 | 统计数据 | 显示个人会员有效期至、未读消息数 |
| 欢迎卡片 | 快捷操作 | 申请个人会员(待审核)、申请单位会员(审核不通过)、资料变更、立即缴费 |
| 侧边菜单 | 导航链接 | 个人中心、会员信息、缴费订单、成长轨迹、我的消息、账号设置、常见问题、意见反馈 |

## 1.2 切换身份

# 切换身份 PRD (产品需求文档)

## 1. 引言

### 1.1 背景

> 同一账号下存在多个会员身份（个人会员、单位会员、任职身份）时，提供身份切换入口，使用户可进入对应身份的功能和数据视图。

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 个人会员 | 已注册并通过审核的个人会员 | 需切换到个人会员视图查看信息、缴费等 |
| 单位管理员 | 单位会员的默认管理员 | 需切换到单位身份管理单位信息、联系人 |
| 单位联系人 | 被单位添加的其他联系人 | 需切换到该单位身份查看单位相关信息 |
| 任职人员 | 拥有任职身份的会员 | 需切换到任职身份查看任职相关信息 |

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
|------|--------|---------|
| 身份列表展示 | 身份卡片 | 以卡片形式展示当前账号下所有有效身份 |
| 身份列表展示 | 当前身份标识 | 标记当前正在使用的身份 |
| 身份列表展示 | 身份分类分区 | 按身份类型（个人/单位/管理员）分区展示 |
| 身份切换 | 点击切换 | 点击身份卡片切换至对应身份 |
| 身份切换 | 权限校验 | 仅展示当前账号绑定的有效身份，失效身份不显示，单位会员已到期的正常展示 |
| 导航 | 返回入口 | 提供返回个人中心的链接 |

---

## 2. 需求说明

### 2.1 身份卡片展示

#### 2.1.1 功能描述

页面按身份类型分区展示当前账号下所有有效会员身份，每个身份以卡片形式呈现，包含身份图标、名称、描述、关键信息（如会员类型、有效期等）。

#### 2.1.2 展示规则

- **个人会员身份卡片**：展示会员姓名、会员类型、有效期
- **单位会员身份卡片**：展示单位名称、会员类型、管理员/联系人角色
- **任职身份卡片**：展示任职机构、职位、任期

#### 2.1.3 业务规则

- SSO 只管理账号，会员系统自己管理会员身份；一个账号可挂多个身份
- 身份切换基于当前账号已绑定的会员身份集合
- 若某身份失效（如退会、联系人变更后被移除），登录后不再展示该身份入口
- 已退会身份、失效身份不可切换进入
- 当只有一个身份时不进入此页面，直接进入

---

### 2.2 当前身份标识

#### 2.2.1 功能描述

在当前使用的身份卡片右上角显示"当前身份"标签，禁止重复切换。

### 2.3 身份切换操作

#### 2.3.1 功能描述

用户点击非当前身份的卡片后，切换至该身份，页面跳转至对应身份的首页。

#### 2.3.2 交互流程

1. **触发条件**：点击非当前身份的身份卡片
2. **操作步骤**：
   - 步骤1：用户点击目标身份卡片
   - 步骤2：系统校验该身份是否有效
   - 步骤3：切换当前身份上下文
   - 步骤4：跳转至对应身份首页
3. **操作反馈**：
   - 成功：页面跳转至对应身份的首页（个人会员→personal-center.html；单位会员→company-home.html，管理员跳转管理端路径）
   - 失败：提示"该身份已失效，无法切换"

#### 2.3.3 业务规则

- 切换后展示的是该身份对应的菜单、数据、消息、证书、待办
- 没有某个身份时，不展示对应身份页签/入口
- 账号维度与身份维度不能混淆，否则会导致消息、权限、历史数据归属错误

---

### 2.4 身份分区展示

#### 2.4.1 功能描述

页面按身份类型分区，各分区标题如下：
- 个人会员身份
- 管理员身份
- 单位会员身份

#### 2.4.2 展示规则

- 若某类型下无身份，则该分区不展示（不显示空分区）
- 管理员身份由后台管理员添加，会员端仅展示，不可自主申请
- 单位会员可有多个身份（如：自己是某单位管理员 + 被另一个单位添加为联系人）

## 3. 业务规则汇总

### 3.1 身份有效性校验规则

| 身份类型 | 有效判断条件 | 失效场景 |
|---------|------------|---------|
| 个人会员 | 会员状态为已生效/正式 | 已退会、已到期未续期 |
| 单位会员 | 单位状态为正式，且当前账号为管理员或联系人 | 单位退会、被移除联系人 |
| 管理员身份 | 管理员状态是否启用 | 管理员删除、禁用 |

### 3.2 跳转规则

| 切换目标身份 | 跳转页面 |
|------------|---------|
| 个人会员 | personal-center.html |
| 单位会员 | company-home.html |
| 管理员身份 | 管理端页面 |

# 任职身份 PRD (产品需求文档)

## 1. 引言

### 1.1 背景

> 展示当前账号下所有会员身份（包括个人会员身份、单位会员身份、任职身份），供会员查看各身份的状态与详情。

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 任职人员 | 拥有任职身份的用户 | 查看任职身份（职位、任期等）|

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
|------|--------|---------|
| 身份列表 | 身份条目展示 | 以列表形式展示所有身份，含名称、任职时间 |
| 身份列表 | 身份状态标签 | 显示各身份的当前状态（任期内、已到期等） |

---

## 2. 需求说明

### 2.1 身份列表展示

#### 2.1.1 功能描述

以纵向列表分页形式展示当前账号下的所有任职身份，每条身份包含：
- **身份名称**：任职机构名称+第N界+任职类型+任职名称；如"中国农学会会员第十届理事会副会长"
- **身份元信息**：任职时间（含起止日期）
- **身份状态标签**：任期内、已到期

#### 2.1.2 业务规则（来自会议逻辑）

- 身份列表数据来源：当前账号在会员系统中绑定的任职身份集合
- 已到期的任职身份，即超过任职结束日期的，仍可在列表中展示，但状态为已到期
- 任职身份由后台管理员添加，非会员自主申请
- 任职身份仅本人可见，不是公告式全员可见

---

### 2.2 身份状态标签

#### 2.2.1 功能描述

每条身份右侧显示状态标签，颜色区分当前有效性。

#### 2.2.2 状态类型定义

| 状态 | 标签颜色 | 适用场景 |

## 8. 业务规则汇总

### 8.1 字段配置规则

- 核心字段（姓名、发展来源、手机号）不能被后台取消
- 扩展字段（研究方向、学术成果等）后台可配置是否启用、是否必填；根据管理端配置做校验
- 手机号由SSO提供，字段禁用编辑

### 8.2 发展来源与初审关系

| 场景 | 规则 |
|------|------|
| 开启初审 | 由该机构初审，会员部终审 |
| 不开启初审 | 直接会员部终审 |

### 8.3 审核流规则

- 审核流可能为1级（终审制）或2级（初审+终审），取决于会员类型配置
- 审核通过前不能缴费，审核驳回后用户可修改信息重新提交
- 后台管理员代为编辑会员资料，也要走同样的审核流，不能直接修改主数据

### 8.4 会员端状态展示

| 状态 | 说明 |
|------|------|
| 审核中 | 申请提交后等待审核 |
| 待缴费 | 审核通过等待缴费 |
| 已通过 | 审核通过且缴费生效 |
| 已驳回 | 审核未通过 |
| 已到期 | 会员资格过期 |

### 8.5 工作单位弱关联

- 工作单位字段用于后续"单位关联个人会员"的弱关联依据之一（按单位名称匹配）
- 个人会员填写工作单位后，可被对应单位会员查询到
- 填写工作单位时，可模糊查询显示单位会员的单位名称

### 2.2 会员概览卡片

- 会员姓名

- 会员状态标签，例如"正常""已到期"
- 会员编号与有效期，例如"会员编号：M2024001 | 有效期至：2026-12-31"
- 操作按钮：查看会员证、变更会员类型、信息变更、续期

#### 2.2.2 交互流程

1. **触发条件**：用户进入会员信息页。
2. **操作步骤**：
   - 步骤1：系统读取当前身份的正式会员数据。
   - 步骤2：渲染头像、姓名、标签、编号、有效期。
  - 步骤3：根据会员类型配置决定是否展示"变更会员类型"按钮。
  - 步骤4：已到期或即将到期展示"续期"按钮，用户可快捷进入续期流程页。
3. **操作反馈**：
   - 成功：概览卡片正常展示。
   - 失败：数据缺失时，对应字段展示"--"或占位符，不阻断页面。
4. **逻辑校验**：
  - 会员编号、有效期、会员类型必须来源于审核通过后的正式数据，不能读取待审核的变更数据。
  - 若当前会员类型在后台配置为"不允许类型变更"，则隐藏"变更会员类型"按钮。
  - 若存在审核中的变更申请，应给出提示并禁用"信息变更"按钮，避免重复提交（参考通用变更校验规则）。
  - 已到期或即将到期（管理端配置的天数来）的展示续期按钮

#### 交互流程

2. **操作步骤**：
   - 步骤1：系统读取当前会员身份。
   - 步骤2：页面跳转到 `register-personal-type.html`。
3. **操作反馈**：
   - 成功：进入续期流程页。
   - 失败：toast提示失败原因。
4. **逻辑校验**：
   - 续期入口应作用于当前身份下的个人会员。
   - 若后续业务限制"仅到期/即将到期会员可续期"，则需在此按钮展示条件中增加状态判断。

#### 2.3.2 交互流程

1. **触发条件**：页面加载完成。
2. **操作步骤**：系统按字段配置读取并展示。
3. **操作反馈**：字段正常展示；空值按占位规则展示。
4. **逻辑校验**：
   - 字段是否展示、是否必填由后台会员类型字段配置决定；

2. **操作步骤**：

3. **操作反馈**：

   - 证书字段必须来源于会员正式数据，不应读取待审核数据。

### 2.9 信息变更与类型变更

#### 2.9.1 功能描述

会员信息变更/资料变更在会员端存在多处入口，统一跳转至资料编辑页（personal-info-edit.html）：
- **会员信息页入口**：会员信息页（personal-info.html）中的"信息变更"按钮。
- **个人中心入口**：个人中心页（personal-center.html）快捷操作区的"会员资料变更"入口。

变更类型分为两类：
- **信息变更**：会员修改已有资料字段后提交变更申请，不支持修改会员类型。
- **变更会员类型**：发起会员类型升级/变更申请，本质上属于会员信息变更的特殊场景，支持变更会员类型，跳转register-personal-type.html页面，重新选择会员类型，返显相同字段的数据，涉及到费用的变更，会员类型变更从审核通过开始计算开始日期，之前的费用根据天数进行退费操作（二期）。

#### 2.9.2 交互流程

1. **触发条件**：用户点击"信息变更"或"变更会员类型"按钮。
2. **操作步骤**：
   - 步骤1：系统校验当前是否存在审核中的信息变更申请或者类型变更申请。
   - 步骤2：若存在，页面提示"当前有审核中的变更申请，请勿重复提交"。
   - 步骤3：若不存在，点击"信息变更"跳转编辑页；点击"变更会员类型"进入register-personal-type.html。
3. **操作反馈**：
   - 成功：正常进入变更流程。
   - 失败：存在审核中申请时，给出明确提示并阻止重复提交。
4. **逻辑校验**：
   - 同一身份下，只要存在一条"审核中的变更申请"，不允许再次提交新的变更申请，资料变更或者类型变更。
   - 会员类型变更或信息变更均必须走审核流，审核通过后才更新正式数据。
   - 后台管理员代为编辑会员资料，也要走同样的审核流，不能直接修改主数据。

## 3. 业务规则补充

### 3.1 身份与数据边界

- SSO 只管理账号，会员系统管理会员身份；一个账号可挂多个身份（个人会员、单位会员、任职身份）。
- 本页展示的是"当前选中的会员身份"数据，切换身份后需重新加载。
- 黑名单身份不可切换进入，前台不再展示该身份入口。

### 3.2 字段配置规则

- 个人会员字段支持后台配置：申请时是否启用、是否必填。
- 核心基础字段（如姓名、发展来源等）不能被后台取消。
- 可预留自定义字段能力，通常放在"其他信息/最后一个板块"。

### 3.3 会员状态与有效期

- 会员状态至少包括：审核中、待缴费、已通过、已驳回、已到期等；本页展示"正常"代表已通过并缴费生效。
- 会员有"入会日期"和"有效期截止时间"两套概念；入会时长按入会日期累计。
- 单位会员到期后支持配置"超期退会阈值/宽容期"，超过阈值自动退会。

### 3.4 审核与变更

- 信息变更、类型变更均需走审核流；驳回意见必填，通过意见可选。
- 审核通过前，变更数据不生效为正式数据。
- 管理端新增或编辑会员资料也必须走审核流，不能跳过。

### 3.5 证书与资料

- 会员证书字段来源于正式数据，支持后台动态配置背景图/模板。
- 管理端可按会员类型配置资料附件，会员端按身份/会员类型查看并下载。

## 4. 通用校验规则

| 校验项 | 规则 |
|--------|------|
| 身份展示校验 | 仅当前账号绑定有效会员身份时，才展示"会员信息"入口 |
| 字段必填校验 | 同一会员类型下，字段必填规则以后台配置为准；核心基础字段不可取消 |
| 级联字段校验 | 级联字段上级变更后，下级值必须清空 |
| 变更重复提交校验 | 存在审核中的变更申请时，禁止再次提交 |
| 类型变更字段校验 | 变更会员类型时，必须满足目标类型所有必填字段要求 |
| 证书数据来源校验 | 证书字段必须读取审核通过后的正式数据 |
| 敏感信息脱敏 | 身份证号、手机号、邮箱、办公电话、通讯地址等需脱敏展示 |

# 信息变更 (personal-info-edit) PRD (产品需求文档)

## 1. 引言

### 1.1 背景

> 信息变更页面向已注册并通过审核的个人会员提供资料修改入口。会员可在后台配置的字段范围内修改本人资料，提交后进入审核流，审核通过后正式数据才生效。

### 1.2 业务逻辑

- 页面加载时读取当前个人会员身份的**正式数据**作为表单默认值。
- 会员类型、缴费方式、发展来源/机构为不可变更字段，仅作只读展示；如需变更需联系管理员。
- 表单字段及必填规则由后台「会员类型字段配置」决定，核心基础字段（如真实姓名、身份证号、手机号等）不可被取消。
- 会员提交变更后，系统生成一条「信息变更申请」进入审核流；审核通过前，变更数据不覆盖正式数据。
- 同一身份下若已存在审核中的信息变更或类型变更申请，禁止再次提交，并给出明确提示。
- 联系方式（手机号、邮箱）的修改仍受 SSO/账号体系约束，本系统仅记录会员资料维度的变更申请。
- **管理端查看信息变更申请时，仅查看哪些字段由原有值变成了新值**

  3. 校验失败：显示错误提示，光标定位到第一个错误字段；
  4. 校验通过：调用后端接口提交变更申请；

## 4. 业务规则补充

### 4.1 变更与审核

- 信息变更必须走审核流，审核通过后才更新正式数据。
- 驳回时审核意见必填，通过时审核意见可选。
- 后台管理员代为编辑会员资料，也要走同样的审核流，不能直接修改主数据。

### 4.2 重复提交校验

- 同一身份下，只要存在一条「审核中的变更申请」，不允许再次提交新的变更申请（包括资料变更和会员类型变更）。
- 页面应在提交前调用接口校验，并给出明确提示。

### 4.3 敏感信息

- 身份证号、手机号、邮箱、通讯地址等敏感信息在展示时建议脱敏处理。
- 联系方式修改不在本系统内直接处理，账号设置、实名认证、微信/邮箱绑定等能力走 SSO/第三方。

## 3. 业务规则补充

### 3.1 缴费流程边界

- 会员缴费遵循"先审核，后缴费"原则：注册/续期/类型变更审核通过后，才生成待缴费订单，0元不产生缴费订单，直接发放会员状态。
- 缴费成功后才成为真正有效会员或延长有效期。
- 支付环节不由本系统直接实现，本系统负责生成订单、拉起支付入口/展示支付链接、回写支付结果。

### 3.2 单位会员线下缴费

- 单位会员缴费重点在线下对公转账场景，管理端可手动录入缴费、确认缴费。
- 线下转账订单需管理端确认到账后，才更新订单状态与会员有效期。
- 管理端可为单位会员手动生成订单，支持按年度补缴历史费用。

### 3.3 订单与有效期

- 订单需明确缴费金额、缴费年度、会员有效期。
- 单位会员支持跨年补缴，不能只按当前自然年度推断。
- 会员有"入会日期"和"有效期截止时间"两套概念；有效期从缴费确认后起算。

### 3.4 发票规则

- 发票信息中的抬头、税号等需符合税务规范。
- 电子发票下载本质为文件或图片下载，发票文件由财务手动上传回写至本系统。

## 4. 通用校验规则

| 校验项 | 规则 |
|--------|------|

## 8. 业务规则汇总

### 8.1 审核流规则

- 审核流可能为1级（会员部终审）或2级（机构初审+会员部终审），取决于会员类型配置
- 审核通过前不能缴费，审核驳回后用户可修改信息重新提交
- 后台管理员代为编辑会员资料，也要走同样的审核流，不能直接修改主数据

### 8.2 会员类型终审调整

- 单位会员终审时，审核人员可根据资质调整会员类型（可升级为更高类型）
- 审核通过后的缴费金额按"审核确认后的会员类型"计算
- 前台缴费方案以审核确认后的类型为准

### 8.3 缴费规则

- 单位会员以线下对公转账为主，审核通过后进入待缴费状态
- 管理端可手动录入缴费、确认缴费
- 线下缴费确认后才更新会员有效期/订单状态

### 8.4 发展来源与初审关系

| 场景 | 规则 |
|------|------|
| 开启初审 | 由该机构初审，会员部终审 |
| 不开启初审 | 直接会员部终审 |

### 8.5 会员端状态展示

| 状态 | 说明 |
|------|------|
| 审核中 | 申请提交后等待审核 |
| 待缴费 | 审核通过等待缴费 |
| 已通过 | 审核通过且缴费生效 |
| 已驳回 | 审核未通过 |
| 超期退回 | 会员资格过期，超过宽恕期后仍未缴费 |

### 8.6 会员管理员规则

- 首次提交该单位注册的用户默认成为该单位会员管理员
- 单位管理员权限：查看单位信息、查看关联个人会员、变更联系人、增加其他联系人

### 8.7 退会规则

- 单位会员到期后支持配置"超期退会阈值/宽容期"
- 超过阈值未缴费则自动退会
- 退会后前台不再展示该单位身份入口

### 2.1 单位头部卡片

在页面顶部展示当前单位会员的核心摘要信息，包括：

#### 2.1.2 交互流程

1. **触发条件**：用户进入单位会员主页。
2. **操作步骤**：

4. **逻辑校验**：
   - 会员编号、入会日期、会员类型必须来源于审核通过后的正式数据，不能读取待审核的变更数据。
   - 已到期单位会员应展示对应状态标签，并可提示缴纳会费/重新入会。
   - 超期退会单位会员应展示对应状态标签，《编辑单位信息》按钮修改为《重新入会》，点击跳转单位会员注册页面，返显相同字段内容。

## 4. 业务规则补充

### 4.1 身份与数据边界

- SSO 只管理账号，会员系统管理会员身份；一个账号可挂多个身份（个人会员、单位会员、任职身份）。
- 本页展示的是「当前选中的单位会员身份」数据，切换身份后需重新加载。
- 失效/已退会身份不可切换进入，前台不再展示该身份入口。

### 4.2 单位管理员与其他联系人

- 首次注册该单位会员的联系人默认成为单位管理员。
- 单位管理员可查看单位信息、查看关联个人会员、变更联系人、增加其他联系人/其他管理员。
- 其他联系人只能查看或做有限操作，不能发起变更联系人。

### 4.3 关联个人会员

- 单位会员可查看「本单位关联的个人会员」。
- 关联逻辑基于个人会员注册/资料中的「工作单位」字段。
- 个人会员可不填工作单位，因此并非所有真实隶属关系都能自动关联。
- 关联个人会员数量仅统计总数，关联有效的会员数据。

### 4.4 资料下载

- 会员证来源于正式数据，支持后台动态配置样式/模板。
- 后台可按单位会员类型配置资料附件，会员端按身份/会员类型查看并下载。

### 4.5 到期与缴费

- 单位会员到期后支持配置「超期退会阈值/宽容期」，超过阈值自动退会。
- 会费缴纳状态应与订单系统保持一致。

## 7. 业务规则

### 7.1 缴费流程

- 单位会员缴费遵循"先审核，后缴费"原则：入会/续期审核通过后生成待缴费订单。
- 单位会员主要通过银行转账（对公转账）方式缴费；线上支付（微信/支付宝）为辅。
- 线下转账订单必须由管理端财务确认到账后，才变更订单状态为"已支付"并更新会员有效期。
- 0元订单（如特殊减免）不产生缴费记录，直接发放会员状态。

### 7.2 有效期管理

- 会员有效期从缴费确认之日起计算。
- 会员有"入会日期"和"有效期截止时间"两套概念。
- 会费宽容期内（如配置365天），会员状态仍展示为"正常"但提示即将到期。

### 7.3 发票规则

- 发票抬头统一为单位会员企业名称，不可随意修改。
- 电子发票文件由财务手动上传至系统后，订单卡片方可展示下载入口。
- 已作废发票不得展示下载按钮。

> 单位会员身份下，展示单条站内通知的完整内容及回复功能，区别于个人身份的消息详情页，归属于单位会员导航体系。

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 单位管理员 | 单位会员默认管理员 | 查看单位收到的通知并回复 |
| 单位联系人 | 被添加的其他联系人 | 查看单位通知（权限范围内）|

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
|------|--------|---------|
| 通知详情 | 通知头信息 | 展示通知标题、发件人、发送时间 |
| 通知详情 | 通知正文 | 展示完整通知内容 |
| 通知详情 | 附件展示 | 展示通知附件，支持下载 |
| 通知回复 | 回复表单 | 输入回复内容，支持上传附件 |
| 导航 | 返回按钮 | 返回单位通知列表 |

---

## 2. 需求说明

### 2.1 通知详情展示

#### 2.1.1 通知头信息

| 字段 | 展示规则 |
|------|---------|
| 通知标题 | 主标题 |
| 发件人 | 显示发件人名称/系统名称 |
| 发送时间 | 格式 YYYY-MM-DD HH:mm |
| 通知正文 | 富文本内容 |

#### 2.1.2 附件展示

- 附件区域显示附件图标和文件名
- 点击附件触发下载

---

### 2.2 通知回复

#### 2.2.1 回复表单

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 回复内容 | 多行文本框 | 是 | placeholder：请输入回复内容... |
| 回复附件 | 文件上传 | 否 | 支持多文件上传 |

#### 2.2.2 交互流程

1. **触发条件**：点击"提交回复"按钮
2. **校验规则**：回复内容不能为空
3. **操作反馈**：
   - 成功：提示"回复成功"，清空表单
   - 失败：提示错误信息

#### 2.2.3 业务规则（来自会议逻辑）

- 单位通知回复按单位身份归属，单位下有权限的人都可查看
- 回复截止时间规则同列表页规则

## 6.1 常见问题

# 常见问题 PRD (产品需求文档)

## 1. 引言

### 1.1 背景

> 展示系统常见问题及答案，以手风琴折叠列表形式呈现，帮助会员快速找到所需帮助信息，减少咨询量。

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 所有用户 | 登录/未登录用户 | 查找常见问题解答 |

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
|------|--------|---------|
| FAQ列表 | 问题列表展示 | 按分类展示常见问题，点击展开/收起答案 |
| FAQ列表 | 分类标签 | 问题显示分类标签（会员相关/缴费相关/申请相关/技术相关）|
| FAQ列表 | 手风琴交互 | 点击问题展开答案，再次点击收起 |

---

## 2. 需求说明

### 2.1 FAQ条目展示

#### 2.1.1 条目结构

| 字段 | 展示规则 |
|------|---------|
| 分类图标 | 左侧，按分类显示不同图标 |
| 问题文本 | 主标题， |
| 分类标签 | 右侧，显示分类名称（字典数据） |
| 展开箭头 | 右侧，点击触发展开/收起 |
| 答案内容 | 折叠区域，展开时显示 |

#### 2.1.2 FAQ分类-字典数据

| 分类 | data-category值 |
|------|----------------|
| 会员相关 | member |
| 缴费相关 | payment |
| 申请相关 | apply |
| 技术相关 | tech |

---

### 2.2 手风琴交互

#### 2.2.1 交互规则

1. **触发条件**：点击问题行任意区域
2. **展开行为**：展开当前问题的答案区域
3. **收起行为**：再次点击已展开的问题行，收起答案
4. **互斥规则**：多条问题可同时展开（非严格手风琴互斥）

---

## 3. 业务规则

### 3.1 FAQ数据来源

- 常见问题本质是后台维护、前台列表展示
- 支持增删改查，类型字典化
- FAQ内容更新后，会员端实时生效

---

## 6.2 意见反馈提交

# 意见反馈提交 PRD (产品需求文档)

## 1. 引言

### 1.1 背景

> 会员端提交意见反馈的表单页面，会员可针对系统使用、服务建议等提交反馈，管理端收到后以站内信形式回复。

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 个人会员 | 已登录个人会员 | 提交对系统或服务的意见建议 |

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
|------|--------|---------|
| 反馈表单 | 反馈类型选择 | 选择反馈类型（问题反馈/建议意见/功能需求等），字典数据 |
| 反馈表单 | 反馈内容输入 | 多行文本框输入详细反馈内容（必填）,最多500字 |
| 表单操作 | 提交反馈 | 提交后进入反馈列表 |
| 表单操作 | 重置表单 | 清空所有输入字段 |

---

## 2. 需求说明

### 2.1 反馈表单字段

| 字段名 | 字段类型 | 必填 | 校验规则 |
|--------|---------|------|---------|
| 反馈类型 | 下拉选择 | 否 | 字典项：问题反馈/建议意见/功能需求/其他 |
| 反馈内容 | 多行文本框 | 是 | 不能为空；提示"请详细描述您的问题或建议" |

---

### 2.2 提交操作

#### 2.2.1 交互流程

1. **触发条件**：点击"提交反馈"按钮
2. **校验规则**：
   - 反馈内容不能为空，最多500字
3. **操作反馈**：
   - 成功：提示"反馈提交成功"，跳转至反馈列表（feedback-list.html）
   - 失败：提示失败原因

#### 2.2.2 重置操作

- 点击"重置"按钮，清空所有表单字段

---

## 3. 业务规则

### 3.1 意见反馈规则

- 会员端提交意见反馈-提交后即完成，，不存在会话式往返
- 管理端回复意见意见反馈意见反馈后，站内信回复

# 会员风采 PRD (产品需求文档)

## 1. 引言

### 1.1 背景

> 展示学会单位会员的风采，以卡片网格形式呈现，支持按会员类型筛选和关键词搜索。

### 1.2 用户角色

| 用户角色 | 描述 | 使用场景 |
|---------|------|---------|
| 游客 | 未登录访问者 | 公开访问数说学会页面 |

### 1.3 功能清单

| 模块 | 功能点 | 功能描述 |
|------|--------|---------|
| 筛选区 | 类型筛选 | 按全部及单位会员类型筛选 |
| 筛选区 | 关键词搜索 | 输入关键词搜索会员名称 |
| 筛选区 | 重置搜索 | 清除搜索条件 |
| 会员卡片列表 | 卡片展示 | 网格布局展示会员卡片（Logo、名称、类型、简介）|

## 2. 需求说明

### 2.1 类型筛选

#### 2.1.1 筛选选项

| 选项 | 筛选条件 |
|------|---------|
| 全部会员 | 展示所有会员 |
| 类型 | 仅展示该单位类型的数据 |

#### 2.1.2 筛选交互

- 点击筛选项高亮当前选中
- 筛选结果实时更新卡片列表

### 2.2 关键词搜索

#### 2.2.1 搜索规则

- 输入关键词后点击搜索按钮触发
- 搜索范围：单位名称（模糊匹配）
- **重置搜索**：点击重置按钮清除关键词并恢复全部展示

---

### 2.3 会员卡片

#### 2.3.1 卡片内容

| 字段 | 展示规则 |

| 单位会员Logo | 无logo时展示周字母 |

| 会员类型 | 如"理事单位"/"普通会员" |

### 2.4 分页

- 每页显示数量：16
- 分页按钮：上一页/下一页/页码数字
- 首页/末页时对应按钮禁用
